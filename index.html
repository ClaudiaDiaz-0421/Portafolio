Análisis de Requisitos

LRF (Lista de Requerimientos funcionales)

Elicitación de necesidades para la automatización de recaudos financieros. Este documento corresponde a un formato liviano de requerimientos funcionales, utilizado para gestionar cambios sobre funcionalidades existentes o el levantamiento de nuevas funcionalidades de baja complejidad, sin requerir el nivel de detalle de un documento de diseño completo como el DRF.

Análisis de Requisitos

DRF (Documento Requerimientos Funcionales)

Especificación funcional para sistemas complejos o desarrollos completamente nuevos, en el marco de la gestión documental para cumplimiento regulatorio (Estándar DRF). A diferencia del LRF —utilizado para cambios menores o funcionalidades de baja complejidad—, el DRF constituye el documento maestro de especificación funcional, con el nivel de detalle requerido para iniciativas de alto impacto.

Definición de Diseño

DDI (Documento Diseño Inicial)

Este documento tiene como propósito representar visualmente el flujo del sistema a partir de los requerimientos funcionales definidos —basado en los documentos DRF o LRF—, permitiendo al usuario final comprender de forma clara e intuitiva el funcionamiento del proyecto antes de su construcción, incluyendo la navegación entre pantallas y la lógica del proceso.

Arquitectura & Calidad

RNF (Requisitos No Func.)

Este artefacto sirve para especificar los atributos de calidad del sistema, tales como rendimiento, seguridad, disponibilidad y escalabilidad, definiendo los límites operativos que garantizan la estabilidad de la solución.

Metodología Ágil / QA

DHU (Documento de Historias de Usuario)

Especificación técnica con mockups y criterios Gherkin, documento más completo con especificación atómica. Sirve para detallar de forma precisa el comportamiento del sistema para el desarrollo y QA.

Matriz de Casos de Prueba
